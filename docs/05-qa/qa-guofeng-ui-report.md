## 3. 问题清单

以下为源码可推导的风险，尚未在浏览器复现；严重级别按潜在影响评估，并非认定本次 UI 改版新引入。

### P1：无效或不支持的备份可能静默覆盖已有数据

- 位置：`index.html:898-900, 1611-1622`。
- 复现建议：在隔离上下文中建立一条菜谱并导出备份；导入合法 JSON `{"schemaVersion":2,"recipes":[]}` 或 `{}`，观察提示及刷新后的数据。
- 预期：拒绝不受支持或无效的备份，提示用户，原数据保持不变；覆盖导入前应明确确认。
- 源码推导：`migrateDatabase` 对不匹配结构返回空库，导入处理随后直接赋给 `db` 并保存，既不报错也不确认，可能覆盖原有快照。此项对应已待办的 `DEV-DATA-001`，动态复现和修复待办。

### P1：读取异常或不支持版本可能在启动时覆盖原快照

- 位置：`index.html:898-900, 942-955, 1642-1643`。
- 复现建议：仅在隔离上下文中写入损坏 JSON 或不支持的 schema 快照，加载页面，再检查原 key；不要在真实用户数据上执行。
- 预期：保留原始数据，明确告知读取失败并提供恢复或导出途径。
- 源码推导：解析异常或结构不匹配返回空库；启动尾部无条件 `saveDatabase()`，写入成功时可能用空库覆盖原快照。`localStorage.setItem` 也没有容量异常处理，保存大图时可能抛错且没有明确提示。

### P2：激活时可能删除同源其他应用的 Cache Storage

- 位置：`service-worker.js:21-25`。
- 复现建议：隔离 origin 下先建立一个非 Cook_Menu 命名的缓存，再注册并激活此 Service Worker，检查该缓存是否保留。
- 预期：只删除属于 Cook_Menu 的过期缓存。
- 源码推导：激活时删除除当前 v3 以外的所有缓存名称；Cache Storage 按 origin 共享，同源其他应用缓存也可能被删除。独占 origin 时影响较小。

### P2：食材和步骤的必填判断可被仅填附属字段绕过

- 位置：`index.html:1374-1385, 1466-1492`。
- 复现建议：隔离环境中新建菜谱，只填菜名、食材用量以及步骤备注或计时，食材名称和步骤正文留空，尝试保存。
- 预期：至少一条有名称的食材和一条有正文的步骤，否则提示。
- 源码推导：过滤逻辑接受只有用量/备注的食材及只有备注/计时的步骤，提交只检查数组长度。需动态确认。
